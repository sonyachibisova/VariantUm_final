# ВариантУм — техническое задание (ТЗ)

> Документ для непосредственной разработки. Содержит функциональные и нефункциональные требования, разбитые на пользовательские истории с критериями приёмки.

---

## 0. Главный принцип: простота для учителя

> **Наш пользователь — учитель, а не айтишник.** Многим тяжело даётся всё новое в технологиях.
> Поэтому понятность и простота важнее функционального богатства. Это сквозное требование ко всем
> историям ниже — при конфликте «больше возможностей» vs «проще понять» выбираем «проще».

Практические правила, обязательные к соблюдению:

1. **Один экран — одно главное действие.** Большая заметная кнопка ведёт дальше; второстепенное спрятано
   за «Дополнительно».
2. **Язык без терминов.** «Создать варианты», а не «инициировать генерацию»; «Скачать», а не «экспорт в формат».
   Никаких кодов ошибок в лицо пользователю — только человеческие фразы с подсказкой, что делать.
3. **Мягкая деградация вместо ошибок.** Если нейросеть сбоит — показываем хоть какой-то результат
   и кнопку «Попробовать снова», а не пустой экран с 500.
4. **Везде подсказки.** Тултипы, примеры заполнения, готовые пресеты (темы, типы вариаций) — чтобы
   не нужно было думать «а что сюда писать».
5. **Обзорная экскурсия по сервису** (онбординг-тур) — показывает «что где и как», запускается при
   первом входе и доступна из шапки в любой момент (см. Эпик 12, статус — в разработке).
6. **Прозрачные лимиты.** У каждого учителя есть лимит обращений к нейросети. Остаток виден заранее,
   а при исчерпании — понятное сообщение «обновится в HH:MM», а не отказ без объяснений (см. Эпик 13).

| Термин | Определение |

| **Градация** | Распределение сложности между вариантами |
| **Инвариант** | Структурный элемент задания, который нельзя менять |

## 2. Функциональные требования

### Эпик 1. Аутентификация

**US-1.1.** Как учитель, я хочу зарегистрироваться по email и паролю, чтобы получить личный кабинет с моими материалами.
- *Критерий приёмки:* регистрация требует email + пароль ≥8 символов. После регистрации — автологин + редирект на онбординг.

**US-1.2.** Как учитель, я хочу войти в систему, чтобы продолжить работу.
- *Критерий приёмки:* JWT в httpOnly-cookie, время жизни 7 дней, refresh-token на 30 дней.

**US-1.3.** Как учитель, я хочу выйти из системы, чтобы защитить данные.
- *Критерий приёмки:* инвалидация refresh-token, очистка cookies.

### Эпик 2. Загрузка эталонного задания (Режим A)

**US-2.1.** Как учитель, я хочу вставить текст задания в форму, чтобы быстро начать генерацию.
- *Критерий:* поле textarea, максимум 10 000 символов, валидация на пустоту.

**US-2.2.** Как учитель, я хочу загрузить файл (PDF, DOCX, TXT), чтобы не копировать вручную.
- *Критерий:* drag-and-drop зона, лимит 10 MB, поддержка форматов pdf/docx/txt, индикатор парсинга.

**US-2.3.** Как учитель, я хочу сфотографировать страницу учебника или загрузить фото, чтобы система распознала текст.
- *Критерий:* поддержка PNG/JPG/HEIC ≤ 10 MB, OCR через Tess4J с русской моделью, показ предпросмотра распознанного текста для правок.

**US-2.4.** Как учитель, я хочу поправить распознанный текст перед анализом, чтобы исправить ошибки OCR.
- *Критерий:* распознанный текст загружается в редактируемое поле, есть кнопка «Принять и продолжить».

### Эпик 3. Анализ эталона (Режим A)

**US-3.1.** Как учитель, я хочу автоматически получить определение предмета, класса, типа и сложности моего задания.
- *Критерий:* после загрузки система вызывает GigaChat-анализатор, возвращает JSON с полями subject, grade, taskType, difficulty, invariants[], variants[]. Время отклика ≤ 5 секунд.

**US-3.2.** Как учитель, я хочу скорректировать определённые системой параметры, если они неверны.
- *Критерий:* все поля анализа выведены в форму с выпадающими списками; учитель может их изменить перед генерацией.

### Эпик 4. Генерация с нуля (Режим B)

**US-4.1.** Как учитель, я хочу выбрать режим «с нуля» на главном экране.
- *Критерий:* на главной два равноправных блока «По эталону» / «По критериям», выбор переводит на соответствующую форму.

**US-4.2.** Как учитель, я хочу заполнить форму критериев, чтобы сгенерировать задания без исходного материала.
- *Критерий:* форма содержит обязательные поля: предмет (выпадающий список ~30 предметов), класс (1–11), тема (текстовое поле), тип задания (задача/тест/упражнение/открытый вопрос/**смешанный**), количество вариантов (слайдер 2–10), количество заданий в варианте (слайдер 1–20), время выполнения (минуты, число), целевая сложность (1–5).
- *Реализовано:* тип «Смешанный» (`MIXED`) — модель сама подбирает сочетание форматов в варианте.

**US-4.2a.** Как учитель, я хочу выбрать тему из готового списка, чтобы не придумывать формулировку с нуля. ✅
- *Критерий:* под полем «Тема» показываются 8–10 подсказок-кнопок, релевантных выбранному предмету
  (например, для математики — «Квадратные уравнения», «Теорема Пифагора», «Задачи на проценты»…).
  Клик подставляет тему в поле; поле остаётся редактируемым. Снижает порог входа для неуверенных пользователей.

**US-4.3.** Как учитель, я хочу выбрать настройку градации сложности между вариантами.
- *Критерий:* радиогруппа «Одинаковая / Возрастающая / Произвольная». При «Произвольной» открывается матрица: для каждого варианта свой уровень сложности.

### Эпик 5. Custom-промпт

**US-5.1.** Как учитель, я хочу добавить своё описание/пожелание к генерации в свободной форме.
- *Критерий:* в форме настройки генерации (оба режима) есть необязательное поле «Дополнительные указания» (textarea ≤ 1000 символов). Содержимое передаётся в промпт GigaChat как приоритетное указание.

**US-5.2.** Как учитель, я хочу видеть примеры удачных custom-промптов, чтобы понять, как пользоваться.
- *Критерий:* рядом с полем — кнопка «Примеры», которая показывает 5–7 готовых формулировок («сделай задачи на тему космоса», «избегай отрицательных чисел», «добавь графики», «используй женские имена», «привязка к ОГЭ»).

### Эпик 6. Просмотр вариантов

**US-6.1.** Как учитель, я хочу видеть все сгенерированные варианты в параллельной таблице.
- *Критерий:* экран с N колонок (горизонтальная прокрутка при N>3), каждая колонка — один вариант, заголовок «Вариант K, сложность X».

**US-6.2.** Как учитель, я хочу видеть, чем варианты различаются, чтобы оценить разнообразие. ✅
- *Критерий:* при включении тумблера «Различия» подсвечиваются цветом изменённые слова/числа относительно первого варианта (вариант 1 — эталон сравнения, варианты 2…N подсвечиваются).

**US-6.3.** Как учитель, я хочу видеть оценку времени решения для каждого варианта.
- *Критерий:* под каждым вариантом — метка «~XX минут», под комплектом в целом — «всего ~YY минут».

### Эпик 7. Редактирование (3 способа)

**US-7.1.** Как учитель, я хочу вручную править текст любого варианта.
- *Критерий:* клик на варианте открывает WYSIWYG-редактор (Tiptap), поддерживает форматирование, формулы (KaTeX), сохранение по Ctrl+S и автосейв через 3 сек простоя.

**US-7.2.** Как учитель, я хочу описать словами, что нужно изменить в одном варианте.
- *Критерий:* у каждого варианта кнопка «Правка через ИИ», открывает поле для промпта, отправляется в GigaChat-правщик одного варианта, ответ заменяет только этот вариант.

**US-7.3.** Как учитель, я хочу применить одно изменение ко всем вариантам сразу.
- *Критерий:* над таблицей вариантов кнопка «Применить ко всем», открывает поле для промпта, отправляется в GigaChat-правщик комплекта.

**US-7.4.** Как учитель, я хочу перегенерировать один вариант с нуля.
- *Критерий:* у каждого варианта кнопка «Перегенерировать», создаёт новый вариант с теми же параметрами, заменяет старый.

**US-7.5.** Как учитель, я хочу добавить новый вариант к комплекту.
- *Критерий:* в конце таблицы кнопка «+ Ещё вариант», добавляет вариант с параметрами по умолчанию (та же сложность что и в комплекте).

**US-7.6.** Как учитель, я хочу удалить ненужный вариант.
- *Критерий:* у каждого варианта кнопка «Удалить» с подтверждением.

### Эпик 8. История версий

**US-8.1.** Как учитель, я хочу откатить последнее изменение, если результат стал хуже.
- *Критерий:* у комплекта в шапке кнопка «Откатить» с указанием времени предыдущей версии.

**US-8.2.** Как учитель, я хочу видеть список всех версий комплекта.
- *Критерий:* боковая панель «История» с временными метками и описанием действия («сгенерировано», «правка через ИИ», «ручная правка»). Клик возвращает к этой версии.

### Эпик 9. Экспорт

**US-9.1.** Как учитель, я хочу экспортировать комплект в PDF, чтобы распечатать.
- *Критерий:* кнопка «Экспорт → PDF», открывает модалку с настройками. Скачивание файла `Вариант_{тема}_{дата}.pdf`.

**US-9.2.** Как учитель, я хочу экспортировать в DOCX, чтобы доработать в Word.
- *Критерий:* кнопка «Экспорт → DOCX», итог — редактируемый .docx со структурой по вариантам.

**US-9.3.** Как учитель, я хочу добавить на лист поля для ФИО, класса, даты, оценки.
- *Критерий:* в модалке экспорта чекбоксы для каждого поля; поля размещаются в шапке каждого варианта.

**US-9.4.** Как учитель, я хочу получить отдельный PDF с ответами «только для учителя».
- *Критерий:* в модалке экспорта чекбокс «Ответы в отдельном файле», скачиваются 2 PDF.

**US-9.5.** Как учитель, я хочу выбрать раскладку на листе.
- *Критерий:* радио «По одному варианту на лист» / «По два варианта на лист» / «Без разрывов».

**US-9.6.** Как учитель, я хочу по желанию подписывать уровень сложности у каждого варианта в экспорте. ✅
- *Критерий:* в окне экспорта галочка «Показывать уровень сложности». Если включена — к заголовку каждого
  варианта в PDF/DOCX добавляется метка «базовый/средний/сложный». По умолчанию выключена.

**US-9.7.** Как учитель, я хочу сохранить комплект картинкой (JPEG), чтобы быстро отправить в мессенджере. ✅
- *Критерий:* в окне экспорта формат «JPEG» наравне с PDF/DOCX; скачивается изображение комплекта вариантов.

**US-9.8.** Как учитель, я хочу открыть оригинал файла, который я загрузил, чтобы свериться с источником. ✅
- *Критерий:* в проекте, созданном из загруженного файла, есть кнопка скачивания исходника (помимо
  просмотра распознанного текста). Так учитель видит и «как было в файле», и «как распознала система».

### Эпик 10. Библиотека

**US-10.1.** Как учитель, я хочу видеть все мои сгенерированные комплекты.
- *Критерий:* раздел «Моя библиотека» со списком комплектов: название, предмет, класс, дата создания.

**US-10.2.** Как учитель, я хочу искать комплекты по предмету/теме/классу.
- *Критерий:* фильтры по предмету (select), классу (select), полнотекстовый поиск по теме.

**US-10.3.** Как учитель, я хочу открыть старый комплект и сделать новый вариант на его основе.
- *Критерий:* клик на комплекте открывает его в режиме просмотра/правки, кнопка «+ Ещё вариант» работает.

### Эпик 11. Рекомендации

**US-11.1.** Как учитель, я хочу видеть подсказки по улучшению комплекта.
- *Критерий:* над таблицей вариантов баннер с 1–3 рекомендациями: «вариант 3 заметно проще», «ответы 1 и 4 совпадают», «можно добавить графический пример».

### Эпик 12. Онбординг 🔜 (в разработке — ключевой для аудитории)

> Это **приоритетный блок** для нашей аудитории: учитель должен с первого захода понять, «что тут вообще
> происходит и куда нажимать». Экскурсия — не украшение, а основной способ снять страх перед новым сервисом.

**US-12.1.** Как новый учитель, я хочу пройти короткую экскурсию по сервису, чтобы понять, что и как работает. 🔜
- *Критерий:* при первом входе автозапуск пошаговой экскурсии (react-joyride), 6–8 шагов с подсветкой ключевых
  элементов и человеческими пояснениями («Здесь загрузите задание или фото», «Тут — готовые варианты, можно править»).
  Кнопка «Пропустить» доступна всегда; экскурсию можно перезапустить из шапки («Помощь → Экскурсия»).
- *Принцип:* объясняем сценарий целиком (загрузка → варианты → правка → скачать), а не отдельные кнопки.

**US-12.2.** Как учитель, я хочу посмотреть видеогайд, чтобы увидеть полный сценарий. 🔜
- *Критерий:* в шапке кнопка «Помощь → Видео», открывается модалка с встроенным видеоплеером (Vimeo/YouTube). Длительность ~2 минуты.

**US-12.3.** Как учитель, я хочу видеть подсказки-тултипы при наведении на кнопки. 🟡
- *Критерий:* у всех ключевых кнопок (генерация, правка, экспорт) — тултип через 500 мс. Часть тултипов уже
  есть (атрибуты `title`), системные tooltip-компоненты — по мере доработки.

### Эпик 13. Безопасность и лимиты

**US-13.1.** Как учитель, я хочу быть уверен, что мои материалы видны только мне.
- *Критерий:* все запросы к БД фильтруются по `user_id`; row-level security в Postgres; ссылки на файлы в MinIO — подписанные с TTL 15 мин.

**US-13.2.** Как владелец сервиса, я хочу ограничить число обращений к нейросети на пользователя. 🔜
- *Критерий (бэкенд):* Bucket4j (+ Redis): N обращений в окно на пользователя (значение из
  `RATE_LIMIT_LLM_PER_HOUR`). При превышении — HTTP 429 c `retryAfter`.
- *Критерий (UX, важно для аудитории):* остаток обращений виден **заранее** — бейдж в шапке
  («Осталось 23 из 30») и/или подсказка у кнопки генерации. При исчерпании — мягкое сообщение
  «Лимит на сегодня исчерпан, обновится в 14:30», а не технический отказ. Учитель не должен
  упираться в стену без объяснения.
- *Статус:* `RateLimitService` — заглушка; `GET /limits/me` зарезервирован (см. API §9). Включение

## 3. Нефункциональные требования

| Категория | Требование |
|---|---|
| **Производительность** | Анализ эталона ≤ 5 сек, генерация комплекта 4 вариантов ≤ 30 сек, парсинг PDF до 50 страниц ≤ 10 сек |

| **Стабильность LLM** | Retry с backoff при ошибках GigaChat (макс 3 попытки), graceful degradation при недоступности (показ ошибки с предложением попробовать позже) |

## 4. Архитектура (краткая, полная — в Документе 1)

**Слои Backend (Spring Boot):**
- **Controller layer** — REST API endpoints (`/api/v1/...`)
- **Service layer** — бизнес-логика (генерация, валидация, экспорт)
- **Integration layer** — клиент GigaChat (HTTP клиент Spring WebClient)
- **Parser layer** — извлечение текста из файлов
- **Repository layer** — JPA-репозитории
- **Domain layer** — entity-классы

**Слои Frontend (React):**
- **Pages** — страницы (Login, Dashboard, Editor, Library, Settings)
- **Features** — функциональные блоки (Generator, Editor, Exporter)
- **Components** — переиспользуемые UI-компоненты
- **Hooks** — кастомные React-хуки
- **API** — клиент бэкенда (TanStack Query)
- **Store** — глобальный стейт (Zustand)
