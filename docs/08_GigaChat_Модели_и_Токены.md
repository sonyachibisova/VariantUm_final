# ВариантУм — Анализ использования GigaChat: модели, запросы, токены

> Документ описывает какие модели GigaChat используются, сколько запросов делается на каждый
> сценарий, как работает рендер фигур, оценку токенов на каждый промпт и рекомендации по
> выбору модели. Обновлён: 25 мая 2026.

---

## 1. Модели GigaChat в проекте

В проекте настроены три «слота» моделей через `.env` / `docker-compose.yml`:

| Переменная | Текущее значение | Назначение |
|---|---|---|
| `GIGACHAT_MODEL` | `GigaChat-2-Pro` | Основная — генерация, правка, Vision |
| `GIGACHAT_MODEL_LITE` | `GigaChat` | Лёгкая/бесплатная — анализ, очистка, рекомендации |
| `GIGACHAT_MODEL_MAX` | `GigaChat-2-Pro` | Тяжёлая (сейчас = Pro, резерв) |

### ⚠️ Важно: несуществующие имена моделей

```
GigaChat-2-Lite  →  НЕ СУЩЕСТВУЕТ (API вернёт 404)
GigaChat         →  ЭТО и есть бесплатная Lite-модель (правильно)
```

### Доступные модели GigaChat на май 2026

| Модель | Цена (синхр.) | Квота Free | Когда использовать |
|---|---|---|---|
| `GigaChat` | **Бесплатно** до 1 000 000 токенов/мес | ✅ есть | Классификация, OCR-очистка, проверки |
| `GigaChat-2-Pro` | **0,5 руб** / 1 000 токенов | ❌ нет (платно) | Генерация, редактирование, Vision |
| `GigaChat-2-Max` | **0,65 руб** / 1 000 токенов | ❌ нет (платно) | Сложные задачи (олимпиады, опц.) |

`GigaChatClient.completion(prompt, temp)` — при 402 (Pro-квота исчерпана) автоматически

там используется `completionWithAttachment()` без фолбэка → при 402 Vision падает на Tesseract.

## 3. Реальное количество запросов (из кода)

> **Важно:** данные получены из анализа `ProjectService`, `VariantService`, `FileController`,
> `AnalyzeController`. Промпты 4 и 7 (validate, estimate_time) **не вызываются**.

### 3.1 Режим A — «По эталону», текстовый ввод

```
Frontend →  POST /analyze/task       →  AnalyzeService        →  GigaChat (Lite)  │  1 запрос
Frontend →  POST /projects           →  GenerateFromRefService →  Pro (+ фолбэк)   │  1 запрос
                                     →  RecommenderService     →  GigaChat (Lite)  │  1 запрос
                                                                                    │
ИТОГО: 2 запроса Lite + 1 запрос Pro = 3 запроса к LLM
```

### 3.2 Режим A — «По эталону», загрузка изображения

```
Frontend →  POST /files/upload       →  VisionExtractionService →  Pro (Vision)   │  1 запрос + 1 upload
Frontend →  POST /analyze/task       →  AnalyzeService          →  GigaChat Lite   │  1 запрос
Frontend →  POST /projects           →  GenerateFromRefService  →  Pro (+ фолбэк)  │  1 запрос
                                     →  RecommenderService       →  GigaChat Lite   │  1 запрос
                                                                                     │
ИТОГО: 2 запроса Lite + 2 запроса Pro + 1 upload = 4 LLM-запроса
```

> При исчерпании Pro-квоты Vision падает на **Tesseract OCR** (формулы распознаёт плохо).

### 3.3 Режим B — «По критериям»

```
Frontend →  POST /projects           →  GenerateFromCritService →  Pro (+ фолбэк)  │  1 запрос
                                     →  RecommenderService       →  GigaChat Lite    │  1 запрос
                                                                                      │
ИТОГО: 1 запрос Lite + 1 запрос Pro = 2 запроса к LLM
```

### 3.4 Операции редактирования

| Операция | Запросы | Детали |
|---|---|---|
| Правка 1 варианта (`/ai-edit`) | **2** | 1 Pro (edit) + 1 Lite (recommend) |
| Правка комплекта (`/ai-edit-all`) | **2** | 1 Pro (edit_all) + 1 Lite (recommend) |
| Перегенерация варианта | **2** | 1 Pro (edit_single) + 1 Lite (recommend) |
| Добавить вариант | **2** | 1 Pro (edit_single) + 1 Lite (recommend) |
| Загрузка PDF/DOCX | **1** | 1 Lite (cleanup) |

> Перегенерация реализована через `AiEditSingleService` с промптом «сделай полностью новый»
> — это 1 запрос, а не 2 (нет отдельного validate).

## 4. Оценка токенов на каждый запрос

> Токенизация GigaChat ≈ 1 токен / 2–4 символа для русского текста.
> Оценки для типичной задачи по математике.

### 4.1 Анализ задания (промпт 1) — Lite

| Компонент | Токены |
|---|---|
| Шаблон (~350 симв.) + текст задания (200–2000 симв.) | **300–1 200 вход** |
| Ответ JSON (~200 симв.) | **~100 выход** |
| **Итого** | **400–1 300 токенов** ✅ бесплатно |

### 4.2 Генерация по эталону (промпт 2) — Pro, 4 варианта

| Компонент | Токены |
|---|---|
| Шаблон + эталон + контекст (600–3600 симв.) | **600–2 000 вход** |
| 4 варианта × ~200 симв. + figure JSON (если есть) | **400–800 выход** |
| **Итого** | **1 000–2 800 токенов** 💰 ~0.5–1.4 руб |

### 4.3 Генерация по критериям (промпт 3) — Pro, 3 вар. × 5 задач

| Компонент | Токены |
|---|---|
| Шаблон + критерии (750–1200 симв.) | **400–700 вход** |
| 15 задач × ~250 симв. + figure JSON | **2 000–3 000 выход** |
| **Итого** | **2 400–3 700 токенов** 💰 ~1.2–1.9 руб |

### 4.4 Правка одного варианта (промпт 5) — Pro

| Компонент | Токены |
|---|---|
| Шаблон + JSON варианта + промпт учителя | **600–1 200 вход** |
| Обновлённый вариант JSON | **300–750 выход** |
| **Итого** | **900–1 950 токенов** 💰 ~0.5–1.0 руб |

### 4.5 Правка всего комплекта (промпт 6) — Pro, 4 варианта

| Компонент | Токены |
|---|---|
| Шаблон + JSON всех вариантов | **1 800–3 200 вход** |
| Обновлённый комплект JSON | **1 600–3 000 выход** |
| **Итого** | **3 400–6 200 токенов** 💰 ~1.7–3.1 руб |

### 4.6 Рекомендации (промпт 8) — Lite

| Компонент | Токены |
|---|---|
| Шаблон + JSON всего комплекта | **1 800–3 200 вход** |
| Список рекомендаций (0–5 штук) | **100–300 выход** |
| **Итого** | **1 900–3 500 токенов** ✅ бесплатно |

> ⚠️ `recommend` отправляет **весь проект** на Lite-модель. Это самый тяжёлый Lite-запрос.
> При ошибке (неверный JSON) `RecommenderService` возвращает пустой список — некритично.

### 4.7 Vision — распознавание изображения (промпт 9) — Pro

| Компонент | Токены |
|---|---|

| Распознанный текст + LaTeX | **250–1 500 выход** |
| **Итого текстовых токенов** | **400–1 650** 💰 Pro Vision |

|---|---|

## 6. Как генерируются картинки (SVG-фигуры)

> **GigaChat НЕ рисует изображения** — только генерирует структурированный JSON.

### Схема работы

```
Промпт генерации (2/3)
  → GigaChat возвращает figure JSON в каждом задании
  → Backend сохраняет в tasks.metadata_json (JSONB)
  → Frontend: FigureSvg.tsx → <svg> прямо в браузере
  → PDF-экспорт: FigureSvgRenderer.java → inline SVG в документ
```

Никаких дополнительных запросов к GigaChat для фигур не делается.
Figure JSON добавляет ~200–500 токенов к стоимости генерации.

### Поддерживаемые типы фигур

| Тип | Когда |
|---|---|
| `geometry` | Любая фигура с именованными точками (универсал) |
| `triangle` | Простой треугольник с числовыми данными |
| `quadrilateral` | Четырёхугольник (прямоугольник, ромб, трапеция) |
| `circle` | Окружность с радиусами/хордами |
| `coordinatePlane` | График функции, точки на плоскости |
| `numberLine` | Числовая ось с отметками |

## 7. Состояние при исчерпанной Pro-квоте (сейчас)

| Операция | Что происходит |
|---|---|
| Генерация (Режим A/B) | ✅ Фолбэк на `GigaChat`, работает |
| Правка варианта/комплекта | ✅ Фолбэк на `GigaChat`, работает |
| Анализ, рекомендации, очистка | ✅ Всегда работают (Lite) |
| Загрузка **изображения** | ⚠️ Падает на **Tesseract** — формулы распознаёт плохо |

**Качество на Lite-фолбэке:**

| Параметр | GigaChat (Lite) | GigaChat-2-Pro |
|---|---|---|
| Генерация заданий | Среднее | Высокое |
| Стабильность JSON | Хуже (нужен `LlmJsonUtil`) | Стабильно |
| LaTeX в ответах | Часто невалидный `\frac` | Корректный |
| Figure JSON | Координаты иногда неточные | Точный |
| Vision | ❌ Не поддерживает | ✅ |
| Скорость | Быстрее ~1.5–2x | Медленнее |

## 9. Параметры запросов к GigaChat

```yaml
# из application.yml
gigachat:
  temperature-generate: 0.7   # генерация/правка — больше вариативности
  temperature-validate: 0.2   # анализ/Vision/recommend — детерминированность
  top-p: 0.9
  max-tokens: 8192             # достаточно для 10 вар. × 5 задач + figure
  timeout-seconds: 120
```

**Retry-политика:**
- 5xx: 3 попытки, backoff 2s → 4s → 8s
- 402: немедленный фолбэк на Lite (только для `completion()`, не для Vision)
- OAuth-токен кешируется 29 минут (`AtomicReference<CachedToken>`) — экономия ~500 мс
