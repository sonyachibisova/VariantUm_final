# Технические требования к описанию решения — ВариантУм

---

## 1. Интеграция с LLM (GigaChat) и используемые промпты

### Подключение

Сервис использует GigaChat API (Сбербанк) в качестве языковой модели. Авторизация — через
OAuth 2.0 по Client ID и Client Secret (scope `GIGACHAT_API_PERS`). OAuth-токен кешируется
на 29 минут, что экономит время на каждом запросе. Взаимодействие реализовано через Spring
WebClient с retry-политикой: при ошибках 5xx — три попытки с экспоненциальным backoff (2→4→8
секунд), таймаут запроса 120–180 секунд.

### Мультимодельная стратегия

В проекте настроены два слота моделей под разные задачи:

| Слот | Модель | Назначение |
|---|---|---|
| Основная (`GIGACHAT_MODEL`) | `GigaChat-2-Pro` | генерация вариантов, AI-правка, распознавание изображений |
| Лёгкая (`GIGACHAT_MODEL_LITE`) | `GigaChat` (бесплатная) | анализ задания, очистка текста, рекомендации |

При исчерпании квоты Pro-модели (`402`) система автоматически переключается на бесплатную
`GigaChat` для генерации и правки — сервис продолжает работу. Для распознавания изображений
(Vision) при недоступности Pro запускается офлайн-фолбэк через Tesseract OCR.

### Устойчивый парсинг ответов LLM

Бесплатная модель `GigaChat` регулярно возвращает невалидный JSON — одиночные обратные слэши
в LaTeX-выражениях, комментарии в стиле `//`. Для решения реализован `LlmJsonUtil`: конечный
автомат `sanitizeJsonEscapes` исправляет невалидные escape-последовательности перед парсингом.
Парсинг двухпроходный — сначала пробуется сырой ответ, при неудаче запускается санитизация.

### Промпты

Все шаблоны промптов хранятся в `backend/src/main/resources/prompts/` в виде текстовых файлов.
Подстановка переменных выполняется утилитой `PromptBuilder` по шаблону `{variable}`.

| Промпт | Назначение | Модель |
|---|---|---|
| `analyze.txt` | анализ эталонного задания: предмет, класс, тип, сложность, инвариантные и вариативные элементы | Lite |
| `generate_from_reference.txt` | генерация N вариантов по эталону с сохранением числа шагов и типа когнитивной нагрузки | Pro |
| `generate_from_criteria.txt` | генерация комплекта с нуля по заданным параметрам | Pro |
| `validate.txt` | проверка сгенерированных вариантов на равносложность и отсутствие совпадений | Pro |
| `ai_edit_single.txt` | правка одного варианта по промпту учителя с сохранением сложности | Pro |
| `ai_edit_all.txt` | единообразная правка всего комплекта по промпту учителя | Pro |
| `estimate_time.txt` | оценка расчётного времени решения для каждого варианта | Pro |
| `recommend.txt` | анализ готового комплекта и формирование рекомендаций по улучшению | Lite |
| `extract_from_image.txt` | извлечение текста, формул (LaTeX), таблиц и описаний графиков из изображения | Pro (Vision) |
| `cleanup_text.txt` | нормализация и исправление ошибок в тексте после парсинга PDF/DOCX | Lite |

Параметры запросов: `temperature` 0.7 для генерации и правки (нужна вариативность), 0.2 для
анализа и распознавания (нужен детерминизм); `top-p` 0.9; `max-tokens` до 32768.

Каждый вызов LLM логируется в таблицу `llm_request_log` (тип промпта, число токенов,
длительность, успех или ошибка) — это основа для rate limiting и аудита.

### Графика: SVG без дополнительных запросов

GigaChat не генерирует изображения — вместо этого возвращает структурированный `figure: {...}`
в JSON каждого задания. Рендер выполняется на клиенте (`FigureSvg.tsx`) и при экспорте в PDF
(`FigureSvgRenderer.java`). Поддерживается 6 типов: `geometry`, `triangle`, `quadrilateral`,
`circle`, `coordinatePlane`, `numberLine`. Данные фигуры хранятся в поле `tasks.metadata_json`.

## 2. Парсинг загружаемых форматов

Извлечение текста реализовано в слое `service/parser/`. Выбор парсера происходит по MIME-типу
через `FileParserRegistry`. После извлечения текст дополнительно обрабатывается
`TextCleanupService` через GigaChat — исправляются ошибки распознавания и нормализуются
математические формулы.

| Формат | Библиотека | Что извлекается |
|---|---|---|
| TXT | Java I/O | текст as-is, затем LLM-очистка |
| PDF | Apache PDFBox | текстовый слой и структура документа |
| DOCX | Apache POI (XWPF) | текст и структура |
| PPTX | Apache POI (XSLF) | текст слайдов |
| PNG / JPG / HEIC | GigaChat Vision (Pro) | текст, формулы в LaTeX, таблицы в Markdown, описания графиков и чертежей |
| Изображение (фолбэк) | Tess4J / Tesseract OCR с русской моделью | текст задачи |

Основной путь для изображений — GigaChat Vision: устойчив к плохому качеству фото, понимает
рукописный текст, распознаёт математические формулы и схемы. Tesseract задействуется только при
недоступности Vision. Ограничение на загружаемый файл — 10 MB.

Распознанный текст перед анализом показывается учителю в редактируемом поле — он может
исправить ошибки распознавания до начала генерации. Исходный файл доступен для просмотра и
скачивания в любой момент.

## 3. Хранение данных

**СУБД:** PostgreSQL 16. Миграции управляются через Flyway. Файлы пользователей хранятся в
MinIO (S3-совместимое объектное хранилище). Кеш и сессии — Redis 7.

Центральная сущность — **комплект вариантов** (`projects`). Структура данных:

| Таблица | Что хранит |
|---|---|
| `users` | учётные записи (email, хеш пароля, роль) |
| `projects` | комплекты вариантов: режим, предмет, класс, тема, тип задания, целевая сложность, градация, статус генерации |
| `variants` | варианты внутри комплекта: порядковый номер, сложность, расчётное время |
| `tasks` | задания внутри варианта: текст, ответ, число шагов, тип, `metadata_json` (фигуры и дополнительные поля) |
| `project_versions` | история версий: полный JSON-снимок состояния комплекта на каждое изменение |
| `recommendations` | рекомендации по комплекту: тип, важность, текст |
| `uploaded_files` | загруженные эталоны: имя, MIME-тип, размер, ключ в MinIO, распознанный текст |
| `llm_request_log` | журнал обращений к LLM: тип промпта, токены, длительность, успех/ошибка |

Поля `params_json` (параметры генерации) и `metadata_json` (дополнительные данные задания)
используют тип JSONB — это позволяет добавлять новые поля без изменения схемы.

Файлы пользователей хранятся в MinIO по ключу `user_{id}/files/{uuid}`. Доступ к файлам
предоставляется через подписанные URL с временем жизни 15 минут.

**Изоляция данных.** Все запросы к БД фильтруются по `user_id`. Дополнительно включён
Row-Level Security в PostgreSQL: политика `projects_user_isolation` ограничивает доступ
через `current_setting('app.current_user_id')`, которое выставляется JDBC-перехватчиком
на каждый запрос. При удалении аккаунта все связанные данные и файлы удаляются каскадно.

## 4. Ограничение запросов к LLM на пользователя

Лимит задаётся переменной окружения `RATE_LIMIT_LLM_PER_HOUR` (по умолчанию 30 запросов
в час на пользователя). Технически реализован через Bucket4j + Redis. Каждое обращение к LLM
фиксируется в `llm_request_log` и засчитывается в лимит.

При превышении лимита сервер возвращает HTTP 429 с заголовком `retryAfter`, указывающим
время до сброса ограничения.

На стороне интерфейса остаток запросов отображается в шапке приложения (например,
«Осталось 23 из 30»). При исчерпании вместо технического отказа показывается понятное
сообщение с точным временем обновления лимита.

Реальное ограничение при работе с GigaChat — именно число запросов, а не стоимость токенов.
Генерация комплекта из 4 вариантов (режим A, текстовый ввод) занимает 3 запроса к LLM и
стоит около 1 рубля; режим B (3 варианта × 5 заданий) — 2 запроса и около 1.5 рубля.

## 5. Форматы экспорта и воспроизведения

**PDF** — основной формат для печати. Генерируется через iText 7. Структура: опциональный
титульный лист с метаданными, варианты с настраиваемыми полями в шапке каждого листа
(ФИО ученика, класс, дата, оценка, подпись родителя), опциональный раздел ответов
«только для учителя». Варианты тестового типа с вариантами ответов А)/Б)/В)/Г) автоматически
форматируются в отдельные строки. Раскладка настраивается: один или два варианта на лист.
Опционально добавляется метка уровня сложности к заголовку каждого варианта.

**DOCX** — для дальнейшего редактирования в Word. Генерируется через docx4j. Структура
аналогична PDF: варианты разбиты по разделам, поля и ответы включаются по выбору.

**Веб-предпросмотр** — перед экспортом все варианты отображаются в параллельной таблице
в браузере. Математические формулы рендерятся через KaTeX, геометрические фигуры — через
SVG-рендерер (`FigureSvg.tsx`). Тумблер «Различия» подсвечивает изменённые фрагменты
относительно первого варианта.

**WYSIWYG-редактор** — Tiptap с поддержкой форматирования и математических формул через KaTeX.
Позволяет вручную редактировать любое задание в любом варианте прямо в браузере.

**Доступ к исходному файлу** — загруженный пользователем файл-эталон доступен для просмотра
в браузере (PDF открывается встроенным просмотрщиком) и скачивания в любой момент.

## 6. Безопасность

- HTTPS для всех соединений
- JWT-аутентификация; токены хранятся в httpOnly-cookie (access: 7 дней, refresh: 30 дней)
- Все секреты передаются через переменные окружения, ни одного ключа в коде
- Row-Level Security в PostgreSQL — пользователь физически не может получить данные другого
- Подписанные URL на файлы MinIO с TTL 15 минут
- Аудит-лог всех обращений к LLM без содержимого заданий (только метаданные)
- Каскадное удаление всех данных при удалении аккаунта

## 7. Нефункциональные требования

| Категория | Требование |
|---|---|
| Производительность | анализ эталона ≤ 5 с; генерация комплекта из 4 вариантов ≤ 30 с; парсинг PDF до 50 страниц ≤ 10 с |
| Совместимость | Chrome, Firefox, Edge — две последние версии; адаптивная вёрстка |
| Стабильность LLM | retry с backoff до 3 попыток; при недоступности — показ понятного сообщения и кнопки «Попробовать снова» |
| Accessibility | контраст WCAG AA, кегль от 16px, клавиатурная навигация |
| Локализация | интерфейс на русском языке |
| Деплой | Docker + docker-compose; Nginx как reverse proxy |

## 8. Стек технологий

**Backend:** Java 21, Spring Boot 3.2 (Web, WebFlux, Security, Data JPA, Data Redis),
PostgreSQL 16 + Flyway, Redis 7, MinIO SDK, Apache PDFBox, Apache POI, Tess4J,
iText 7, docx4j, Bucket4j, JJWT, Lombok, MapStruct, Springdoc OpenAPI.

**Frontend:** React 18 + TypeScript, Vite, TanStack Query, Zustand, Tailwind CSS,
Tiptap, KaTeX, react-hook-form + zod, react-joyride, lucide-react.

**Инфраструктура:** Docker + docker-compose, Nginx, PostgreSQL 16, Redis 7, MinIO.
