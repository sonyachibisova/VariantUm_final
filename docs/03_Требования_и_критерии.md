- **Логика подачи:** строго следуем порядку 9 разделов выше

## 5. Критерии оценивания — соответствие нашего решения

> Из требований: 100 баллов максимум, 7 критериев. Расписано, как каждый критерий закрывается.

### 5.1 Продуктовое исследование и прототип (10 баллов)

**Целимся: 10/10.** Что для этого делаем:
- Краткий отчёт продуктового исследования: 5–7 интервью с учителями, выводы, барьеры, приоритетные сценарии
- Полностью заполненная карточка прототипа (см. Документ 2)
- Отчёт прикладываем PDF-файлом, ссылка в презентации

**Что НЕ должно произойти:** карточка заполнена частично, отчёт без выводов → 5 баллов.

### 5.2 Воспроизводимость полного сценария (20 баллов)

**Целимся: 20/20.** MVP должен позволять пройти весь путь без блокирующих багов:

```
Ввод контекста + загрузка → Анализ → Генерация → 
→ Редактирование → Параллельное сравнение → Экспорт PDF/DOCX
```

**Что НЕ должно произойти:** обрывается на экспорте, не работает OCR, падает на больших PDF → 10 баллов.

**Митигация:** к 22 мая отлажен «золотой путь» (один проверенный сценарий с математической задачей), к 27 мая — расширенный (4 предмета).

### 5.3 Качество генерации и обработки материалов (20 баллов)

**Целимся: 20/20.** Что обеспечиваем:
- Парсинг всех заявленных форматов: TXT, PDF, DOCX, PPTX, PNG/JPG с OCR
- Промпт-инжиниринг с учётом контекста темы, типичных ошибок учеников и сохранения уровня сложности (см. Документ 1, разд. 4.4)
- Двухпроходная генерация: после генерации валидатор проверяет инварианты, при нарушении — перегенерация
- Методическая релевантность: тестируем на 50 эталонах из 5 предметов до защиты

**Что НЕ должно произойти:** парсинг работает только для TXT, промпт без указания типичных ошибок учеников → 10 баллов.

### 5.4 Гибкость редактирования и настройка параметров (10 баллов)

**Целимся: 10/10.** Что реализуем:
- **Два режима генерации:** «по эталону» и «с нуля по критериям»
- **Три способа правки вариантов:**
  - Ручная правка в WYSIWYG-редакторе на Tiptap с поддержкой формул KaTeX
  - Промпт-правка одного варианта («сделай реалистичные числа в задаче 3»)
  - Промпт-правка всего комплекта одной командой («замени автомобили на поезда»)
- **Дополнительный промпт-уточнение** от учителя на любом этапе генерации
- **Градация сложности:** одинаковая / возрастающая (базовый → продвинутый → углублённый) / произвольная шкала
- **Настройка параметров вариации:** количество (2–10), типы (числа/имена/контекст/порядок/лексика), фиксация частей условия
- **Настройка экспорта:** поля ФИО/класс/дата/оценка, раскладка, шрифт, размер
- **История версий:** сохраняем исходно сгенерированный набор + все правки с возможностью отката

**Что НЕ должно произойти:** можно только править текст, но нельзя менять параметры → 5 баллов.

### 5.5 Форматы вывода, воспроизведение и статистика (10 баллов)

**Целимся: 10/10.** Что реализуем:
- ≥ 2 формата: PDF (iText 7) + DOCX (docx4j)
- Веб-предпросмотр перед экспортом
- Персональные ссылки на просмотр сгенерированного комплекта (опционально)
- Статистика: сколько раз учитель использовал каждое задание, какие варианты чаще правились, среднее время на генерацию. Доступна в разделе «Моя библиотека»

**Что НЕ должно произойти:** только PDF без статистики → 5 баллов.

### 5.6 Техническая реализация и архитектура (10 баллов)

**Целимся: 10/10.** Что обеспечиваем:
- Чёткая диаграмма архитектуры в презентации: Frontend (React) ↔ Backend (Spring Boot) ↔ GigaChat ↔ БД (PostgreSQL + Redis + MinIO)
- Стабильно работающий веб-сервис на VPS
- Корректная интеграция с GigaChat через официальный API
- Код в публичном репозитории с README, инструкцией `docker-compose up`, документацией API через Swagger/OpenAPI

**Что НЕ должно произойти:** в качестве БД файл, нет инструкции → 5 баллов.

### 5.7 Безопасность, лимиты и конфиденциальность (10 баллов)

**Целимся: 10/10.** Что реализуем:
- Bucket4j ограничивает: 30 запросов к LLM на пользователя в час
- Row-level security в PostgreSQL: SQL-фильтр по `user_id` во всех запросах
- Изолированные бакеты MinIO: `user_{id}/...`, доступ только по подписанным URL с TTL 15 минут
- JWT-аутентификация, secure HTTPS, secure cookies
- Логи без PII (только user_id, никакого текста заданий)
- Аудит-лог всех генераций

**Что НЕ должно произойти:** реализовано только одно из двух (только rate limit или только изоляция) → 5 баллов.

### 5.8 Оформление презентации и документации (10 баллов)

**Целимся: 10/10.** Что обеспечиваем:
- Все 9 разделов из требований раскрыты
- Визуализация: диаграмма архитектуры, таблица сравнения, мокапы интерфейса
- Все ссылки кликабельны: MVP, GitHub, карточка прототипа, отчёт исследования, скринкаст
- Минимум текста, акцент на схемах и цифрах
- Таблицы для рисков и дорожной карты

**Что НЕ должно произойти:** нет блока сравнения «до/после», нет рисков → 5 баллов.

## 7. Что отличает ВариантУм от других команд

Дополнительные баллы при защите можно получить за то, что не входит в формальные критерии, но впечатляет жюри. Наши козыри:

1. **Java Spring на бэкенде** — мы единственные (вероятно), кто пишет под стек СберТех. Это сигнал «готовы к интеграции после хакатона».
2. **OCR из коробки** — большинство команд ограничится TXT/PDF. У нас фото-страницы методичек работают сразу.
3. **Двухпроходная генерация с валидатором** — это методически правильный подход. Большинство команд сделает один промпт, у нас второй проход гарантирует сохранение сложности.
4. **Onboarding-тур + видеогайд + большие кнопки** — accessibility для возрастных учителей. Никто не делает этого специально, у всех «современный UX для миллениалов».
5. **Печатные поля ФИО/класс/дата** — учителя оценят, потому что это их реальная боль (вписывают ручкой каждый раз).
6. **Лента рекомендаций по комплекту** — «вариант 3 проще остальных» — это уникальная функция. Никто из конкурентов так не делает.
7. **Оценка времени решения** — даёт учителю предсказуемость («контрольная займёт 35 минут»).
8. **Готовность к экосистеме СберОбразования** — упоминаем edu.sber.ru, ed-industry.ru, потенциал интеграции в СберКласс.

### Возможные вопросы жюри и заготовки ответов

1. *«Почему GigaChat, а не GPT-4?»* → Безопасность данных РФ + бесплатный план для образования + готовность к интеграции в СберОбразование.
2. *«Как гарантируете одинаковую сложность?»* → Двухпроходная генерация: после первого промпта валидатор проверяет число шагов решения и тип когнитивной нагрузки.
3. *«Почему Java Spring, а не Python?»* → Стек СберТех, простота интеграции в edu.sber.ru после хакатона. Транзакционность и безопасность из коробки.
4. *«Что если учитель уйдёт из системы — где его варианты?»* → Каскадное удаление по GDPR-like процедуре. Изоляция данных на уровне Postgres row-level security.
5. *«Чем вы лучше ЯКласса?»* → ЯКласс — банк готовых заданий. Мы — генератор по личному эталону учителя. Это разные продукты, мы дополняем друг друга.
6. *«Как монетизировать?»* → Freemium: 5 генераций в день бесплатно, безлимит — 299 ₽/мес. Корпоративный план для школ — от 9 990 ₽/мес. Но монетизация — после хакатона.
