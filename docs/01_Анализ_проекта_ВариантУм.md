# ВариантУм — полный анализ проекта

**Кейс:** №4. ИИ-генератор вариантов заданий
**Хакатон:** «Искусственный интеллект для образования: автоматизация рутинных задач»
**Организаторы:** СберОбразование × Школа 21
**Защита:** 28 мая 2026

---

## 1. Что такое ВариантУм

**ВариантУм** — веб-сервис генерации школьных заданий через GigaChat, поддерживающий **два режима работы**:

**Режим A. «По эталону»** — учитель загружает готовое задание (текст, PDF, DOCX, фото), сервис анализирует структуру и создаёт N вариантов того же типа и сложности. Используется, когда у учителя уже есть наработка из учебника, методички или собственного архива.

**Режим B. «По критериям» (с нуля)** — учитель задаёт параметры: предмет, класс, тема, тип задания, количество, желаемое время решения, уровень сложности, дополнительные пожелания. Сервис генерирует задания и варианты с нуля. Используется, когда нужно срочно сделать материал с чистого листа.

В обоих режимах работают **общие фишки**:
- Дополнительный промпт-пояснение от учителя на любом этапе («сделай задачи про космос», «избегай отрицательных чисел», «добавь графики»)
- Градация сложности: можно генерировать варианты одинаковой сложности, либо с возрастанием (базовый → продвинутый → олимпиадный), либо с заданным распределением
- Редактирование вариантов на любой стадии: вручную (WYSIWYG), через промпт к одному варианту, через промпт ко всему комплекту

Ключевая ценность — **сохранение дидактической цели**: даже когда сложность намеренно меняется по градации, тип когнитивной нагрузки и структура задания остаются осмысленными. Это то, чего невозможно добиться ChatGPT-обёрткой без методического слоя.

### Слоган
> «Один пример — десять вариантов. Один промпт — целая контрольная.»

## 2. Проблема и пользователи

### 2.1 Целевая аудитория

**Основной сегмент:** учителя 1–11 классов общеобразовательных школ РФ по всем предметам, прежде всего по математике, физике, химии, русскому языку, английскому языку, информатике (там, где варианты особенно востребованы).

**Поведенческие типы:**

| Тип | Описание | Доля | Боль |
|---|---|---|---|
| «Классик» (45+ лет) | Опытный предметник, работает с печатными раздатками | ~50% | Долго делает вручную, боится новых интерфейсов |
| «Прагматик» (30–45 лет) | Уверенный пользователь ПК, ищет инструменты экономии времени | ~35% | Не доверяет качеству ИИ, нужны гарантии корректности |
| «Цифровой» (до 30 лет) | Использует ChatGPT/Я.GPT, но не доверяет результату | ~15% | Хочет инструмент именно для образования, а не универсальный |

**Вторичный сегмент:** методисты, репетиторы, преподаватели колледжей и СПО (для будущего масштабирования).

### 2.2 Сценарий столкновения с проблемой

Учительница математики Марина Петровна готовит контрольную для 7 класса по теме «Линейные уравнения». В учебнике есть один эталонный пример. Ей нужно 4 варианта по 6 задач, чтобы рассадить класс через ряд и исключить списывание.

**Что происходит сейчас:**
1. Берёт оригинальную задачу
2. Вручную меняет числа («2x + 3 = 11» → «3x + 5 = 14»)
3. Решает каждый вариант, чтобы проверить корректность ответа
4. Проверяет, что все варианты решаются за одинаковое время и не дают «красивых» совпадений
5. Оформляет в Word, печатает

**Что мешает:**
- На 24 задачи (4 варианта × 6 задач) уходит 2–3 часа
- Сложность поплывёт: в одном варианте корень целый, в другом — дробный
- При замене «в прогрессии» (5, 10, 15, 20) ученики быстро вычисляют логику
- Если поменять контекст («скорости поездов» → «работа труб»), нужно проверить корректность всей задачи заново

**Чего хочет:** загрузить эталон, нажать «4 варианта», получить готовый PDF с ответами для себя и без ответов — для печати ученикам. Время на подготовку — 5 минут вместо 3 часов.

### 2.3 Барьеры
- Страх «ИИ напишет ерунду» → нужен превью + редактирование
- Боязнь утечки наработок → жёсткая изоляция данных
- Сложные интерфейсы → онбординг + видеогайд
- Нет интернета в кабинете → экспорт в PDF/DOCX без зависимости от веба при печати

## 3. Решение

### 3.1 Идея в одном предложении
Учитель загружает эталон → выбирает параметры вариации → получает N вариантов в табличном виде сравнения → редактирует → выгружает в PDF/DOCX с полями ФИО/класс/дата.

### 3.2 Основные пользовательские сценарии

**Сценарий 1. Быстрая мультипликация задачи (Режим A — по эталону)**
1. Учитель вставляет текст задачи в поле ввода
2. Выбирает «4 варианта», тип вариации — «числа»
3. Через 15–30 секунд видит 4 варианта в параллельном просмотре
4. Бегло пробегает глазами, нажимает «Экспорт в PDF»
5. Печатает

**Сценарий 2. Мультипликация из методички (Режим A)**
1. Учитель загружает PDF с задачами из методички
2. Сервис распознаёт текст, показывает список задач
3. Учитель отмечает «вот эти 6 задач, по 4 варианта на каждую»
4. Получает готовый комплект из 24 задач (4 контрольные)
5. Корректирует одно нестыковочное место в варианте 3, перегенерирует только его
6. Экспортирует с полями для ФИО/класса/даты

**Сценарий 3. Срочная пересдача (Режим A)**
1. Ученик пропустил контрольную → нужен «свежий» вариант, не совпадающий с оригиналом
2. Учитель открывает сохранённое в библиотеке задание
3. Жмёт «+1 вариант», получает один новый, печатает
4. На всё — 30 секунд

**Сценарий 4. Контрольная с чистого листа (Режим B — по критериям)** 🆕
1. У учителя нет под рукой материалов, но завтра нужна самостоятельная
2. Заполняет форму: предмет — алгебра, класс — 8, тема — «Квадратные уравнения», тип — задача, количество вариантов — 3, заданий в варианте — 5, время на работу — 25 минут
3. В поле дополнительного промпта пишет: «Сделай 5-ю задачу с параметром, остальные без»
4. Получает 3 готовых варианта по 5 задач каждый, оценка времени — 23 минуты на вариант
5. Экспортирует

**Сценарий 5. Контрольная с градацией сложности (Режим B + градация)** 🆕
1. Учитель готовит дифференцированную работу: слабые, средние, сильные
2. Заполняет критерии и выбирает «Градация: базовый → продвинутый → углублённый»
3. Получает 3 варианта возрастающей сложности на одной теме
4. Слабые ученики получают вариант 1, средние — 2, сильные — 3
5. Время решения для каждого — соответственно 20/25/35 минут

**Сценарий 6. Доработка через промпт ко всему комплекту** 🆕
1. Учитель сгенерировал 4 варианта по физике, видит результат
2. В поле «Доработать комплект» пишет: «Замени все примеры с автомобилями на примеры с поездами»
3. Все 4 варианта одновременно перегенерируются с новым контекстом, сохраняя сложность
4. Если результат лучше — принимает, если хуже — откатывает к предыдущей версии (история есть)

**Сценарий 7. Точечная правка через промпт к одному варианту** 🆕
1. Из 5 сгенерированных вариантов один по физике вышел с нереалистичными числами (скорость 5000 км/ч у машины)
2. Учитель не правит вручную, а пишет в промпте к этому варианту: «Сделай реалистичные значения скорости и расстояния»
3. Вариант 3 перегенерируется индивидуально, остальные не меняются

### 3.3 Сравнение с существующими решениями

| Параметр | Ручное создание | ChatGPT / Я.GPT | Тестораздел.рф, ЯКласс | **ВариантУм** |
|---|---|---|---|---|
| Время на 4 варианта | 1–3 часа | 10–20 мин | банк готовых, нет генерации | **1–3 минуты** |
| Режим «по эталону» | Возможен | Частично | Нет | **Да, с парсингом и OCR** |
| Режим «с нуля по критериям» | 2–4 часа | Возможен, но без структуры | Только банк | **Да, с полным контролем параметров** |
| Сохранение сложности | Зависит от учителя | Часто плывёт | Гарантировано | **Контролируется промптом + валидацией** |
| Градация сложности (базовый/продвинутый/углублённый) | Вручную | Нет | Нет | **Да, авто-генерация по шкале** |
| Дополнительный промпт от учителя | — | Да | Нет | **Да, на любом этапе** |
| Промпт-правка одного варианта | — | Только всего ответа | Нет | **Да, точечно** |
| Промпт-правка всего комплекта | — | Нужно начинать заново | Нет | **Да, одной командой** |
| Парсинг PDF/DOCX/фото | Нет | Ограниченно | Нет | **Есть, с OCR** |
| Параллельное сравнение | Вручную | Нет | Нет | **Есть** |
| Поля ФИО/класс/дата при печати | Вручную | Нет | Иногда | **Есть, настраиваемые** |
| Данные внутри РФ | — | Нет | Да | **Да (GigaChat)** |
| Изоляция данных учителя | — | Нет | Частично | **Полная** |
| Оценка времени решения | — | Нет | Нет | **Есть (по сложности и числу шагов)** |
| Рекомендации по улучшению | — | Нет | Нет | **Есть** |
| История версий комплекта | Нет | Нет | Нет | **Есть, с откатами** |

**Главные отличия от ChatGPT-обёрток:** методическая валидация, два режима работы, промпт-правки разной гранулярности, интеграция с печатью, библиотека, изоляция данных, специфика школьной программы РФ.

## 4. Техническая реализация

### 4.1 Архитектура

```
┌──────────────┐    HTTPS    ┌─────────────────┐    REST     ┌──────────────┐
│   Frontend   │────────────▶│   Backend       │────────────▶│  GigaChat    │
│   React/TS   │             │   Java Spring   │             │     API      │
│              │◀────────────│   Boot 3.x      │◀────────────│              │
└──────────────┘             └────────┬────────┘             └──────────────┘
                                      │
                       ┌──────────────┼──────────────┐
                       ▼              ▼              ▼
                 ┌──────────┐  ┌──────────┐  ┌──────────────┐
                 │PostgreSQL│  │  Redis   │  │  MinIO/S3    │
                 │   DB     │  │  cache + │  │ файлы юзера  │
                 │          │  │ ratelim. │  │              │
                 └──────────┘  └──────────┘  └──────────────┘
```

**Поток данных:**
1. Клиент отправляет файл/текст → Backend
2. Backend парсит контент (Apache PDFBox / Apache POI / Tesseract OCR)
3. Извлечённый текст идёт в **Анализатор задания** (Spring-сервис) → определяет предметную область, тип, вариативные/инвариантные элементы, оценивает сложность
4. **Генератор вариантов** формирует промпт с контекстом и параметрами вариации → GigaChat API
5. **Валидатор** проверяет корректность результата (формат, число шагов, отсутствие дубликатов)
6. Результат сохраняется в PostgreSQL, файлы — в MinIO, метаданные кешируются в Redis
7. Клиент получает варианты через WebSocket (стриминг по мере готовности)

### 4.2 Стек технологий

**Backend (Java)**
- **Java 21 (LTS)** — современная LTS-версия
- **Spring Boot 3.2** — фреймворк
- **Spring Web** — REST API
- **Spring Security + JWT** — аутентификация
- **Spring Data JPA + Hibernate** — работа с БД
- **Spring WebFlux/WebSocket** — стриминг ответов от GigaChat
- **Apache PDFBox** — парсинг PDF
- **Apache POI** — парсинг DOCX/PPTX
- **Tess4J (Tesseract OCR)** — распознавание текста с фото
- **iText 7 / OpenPDF** — генерация PDF на выходе
- **docx4j** — генерация DOCX на выходе
- **Bucket4j** — rate limiting (запросы к LLM на пользователя)
- **Lombok, MapStruct** — boilerplate reduction
- **JUnit 5 + Mockito** — тесты

**Почему Java Spring:**
1. Совпадает со стеком СберТех/СберОбразования (Java — основной язык Сбера) → проще интеграция в их экосистему после хакатона
2. Production-ready: транзакции, безопасность, масштабирование «из коробки»
3. Сильная типизация → меньше багов при работе со структурированными данными от LLM
4. Spring Security даёт серьёзный уровень изоляции данных (критерий 10 баллов в оценке)

**Frontend**
- **React 18 + TypeScript** — UI
- **Vite** — сборка
- **TanStack Query** — работа с API
- **Zustand** — стейт-менеджмент (легче Redux)
- **Tailwind CSS + shadcn/ui** — стили и компоненты
- **react-hook-form + zod** — формы и валидация
- **Tiptap** — WYSIWYG-редактор для правки задач (включая формулы через KaTeX)
- **react-dropzone** — загрузка файлов
- **react-joyride** — гайд-онбординг по интерфейсу (наша фишка)

**База данных и инфраструктура**
- **PostgreSQL 16** — основная БД (задания, пользователи, варианты, история)
- **Redis 7** — кеш + rate limiting + сессии
- **MinIO** — S3-совместимое хранилище для загруженных файлов
- **Docker + docker-compose** — контейнеризация для развёртывания
- **Nginx** — reverse proxy + статика

**LLM-интеграция**
- **GigaChat API** — мультимодельная стратегия: `GigaChat` (бесплатная, анализ/очистка) + `GigaChat-2-Pro` (генерация, правка) + `GigaChat-2-Pro` как Max (опц.)
- Автофолбэк: если Pro возвращает 402 (квота), генерация автоматически переключается на бесплатную `GigaChat`
- **GigaChat Embeddings** — для будущей системы рекомендаций похожих заданий
- Fallback на YandexGPT не предусматриваем, чтобы упростить MVP

### 4.3 Парсинг входных форматов

| Формат | Библиотека | Что извлекаем |
|---|---|---|
| TXT | Java I/O | Текст as-is + LLM-очистка |
| PDF | Apache PDFBox | Текстовый слой + структура → LLM-очистка |
| DOCX | Apache POI (XWPF) | Текст + структура → LLM-очистка |
| PNG/JPG/TIFF/BMP | **GigaChat Vision** | Текст + формулы (LaTeX) + таблицы (Markdown) + описания графиков/чертежей |
| GIF/WEBP | Перекодировка в PNG → GigaChat Vision | то же |
| Изображение (фолбэк при сбое Vision) | Tess4J + русская модель → LLM-очистка | OCR с текстом задачи |

**Качество распознавания.** Основной путь для изображений — GigaChat Vision (модель GigaChat-Pro):
она устойчива к плохому качеству фото, распознаёт рукописный текст, формулы, **графики и таблицы**,
чего не умеет классический OCR. Tesseract оставлен офлайн-фолбэком. Текст из текстовых форматов
дополнительно прогоняется через LLM-очистку (`TextCleanupService`) для исправления ошибок парсинга.

**Графика и таблицы.** Геометрические фигуры и графики генерируются GigaChat как структурированный JSON (`figure: {type, points, segments, …}`) и рендерятся в SVG — на фронте через `FigureSvg.tsx` и в PDF через `FigureSvgRenderer.java`. Поддерживается 6 типов: `geometry` (универсальный), `triangle`, `quadrilateral`, `circle`, `coordinatePlane`, `numberLine`. Таблицы — как Markdown; экспорт конвертирует их в HTML-таблицы PDF.

### 4.4 Работа с GigaChat: промпт-инжиниринг

У сервиса **7 типов промптов**, каждый со своей задачей:

#### Промпт 1. Анализатор задания (Режим A)
Принимает текст эталонного задания → возвращает JSON с предметом, классом, типом, сложностью, инвариантными и вариативными компонентами.

#### Промпт 2. Генератор по эталону (Режим A)
```
Ты — методист с 20-летним опытом подготовки школьных заданий.

ЭТАЛОННОЕ ЗАДАНИЕ:
{текст задания}

АНАЛИЗ:
- Предмет: {предмет}, Класс: {класс}, Тип: {тип}
- Инвариантные элементы (НЕ менять): {операции, тип ответа, число шагов}
- Вариативные элементы (МОЖНО менять): {числа, имена, контекст}
- Целевая сложность: {уровень в 1-5}

ПАРАМЕТРЫ:
- Количество вариантов: {N}
- Типы вариации: {выбранные}
- Запреты: {фиксированные элементы}
- Градация сложности: {одинаковая / возрастающая / по шкале [1,2,3]}
- Дополнительные указания учителя: {custom_prompt или пусто}

ТРЕБОВАНИЯ:
1. Сохрани форму ответа.
2. При одинаковой сложности — сохрани число шагов решения.
3. При градации — последовательно добавляй/убирай шаги решения.
4. Не делай «красивых» чисел.
5. Ответы во всех вариантах должны быть РАЗНЫМИ.
6. Учти дополнительные указания учителя как приоритет.

ФОРМАТ: строгий JSON со списком variants, каждый с id, text, answer, steps, estimated_minutes, difficulty_level.
```

#### Промпт 3. Генератор «с нуля» по критериям (Режим B) 🆕
```
Ты — методист, создаёшь школьные задания с нуля.

ПАРАМЕТРЫ:
- Предмет: {предмет}
- Класс: {класс}
- Тема: {тема}
- Тип задания: {задача / тест / упражнение / открытый вопрос}
- Количество вариантов: {N}
- Заданий в одном варианте: {M}
- Время на выполнение всего варианта: {время} минут
- Целевая сложность: {1-5}
- Градация сложности между вариантами: {одинаковая / возрастающая / по шкале}
- Дополнительные указания учителя: {custom_prompt}

ТРЕБОВАНИЯ:
1. Все задания должны строго соответствовать школьной программе для указанного класса.
2. Внутри одного варианта задания должны быть РАЗНОГО типа (если M > 1): расчётные, на понимание, на анализ.
3. Суммарное расчётное время решения всех заданий в варианте ≈ {время} ± 15%.
4. Между вариантами одной и той же сложности задания должны быть взаимозаменяемыми (одинаковое число шагов).
5. При градации сложности — варианты должны различаться числом шагов, абстрактностью, объёмом анализа.
6. Учитывай дополнительные указания учителя как приоритет.

ФОРМАТ: JSON со списком variants, каждый содержит массив tasks, каждое task — text, answer, steps, estimated_minutes, type.
```

#### Промпт 4. Валидатор сложности
Принимает сгенерированные варианты → проверяет, что инварианты соблюдены (число шагов, тип, форма ответа). При нарушении возвращает причину для перегенерации.

#### Промпт 5. Оценщик времени решения
Оценивает в минутах среднее время на решение каждого варианта и комплекта в целом для среднего ученика указанного класса.

#### Промпт 6. Промпт-правка одного варианта 🆕
```
ИСХОДНЫЙ ВАРИАНТ:
{вариант N полностью}

КОНТЕКСТ КОМПЛЕКТА:
- Предмет: {предмет}, Класс: {класс}, Тема: {тема}
- Целевая сложность: {уровень}

УКАЗАНИЕ УЧИТЕЛЯ:
{что нужно изменить, естественным языком}

ТРЕБОВАНИЯ:
1. Выполни ТОЛЬКО запрошенное изменение.
2. Сохрани сложность и число шагов.
3. Не меняй структуру варианта (если не просили).

ФОРМАТ: обновлённый вариант в том же JSON-формате.
```

#### Промпт 7. Промпт-правка всего комплекта 🆕
```
ИСХОДНЫЙ КОМПЛЕКТ ИЗ {N} ВАРИАНТОВ:
{все варианты}

УКАЗАНИЕ УЧИТЕЛЯ:
{что изменить во всём комплекте}

ТРЕБОВАНИЯ:
1. Примени изменение ко ВСЕМ вариантам единообразно.
2. Сохрани взаимозаменяемость (или градацию, если она была) между вариантами.
3. Сохрани общую сложность.

ФОРМАТ: обновлённый комплект в исходном JSON-формате с сохранением структуры.
```

#### Промпт 8. Рекомендатор
Анализирует готовый комплект → предлагает улучшения: «вариант 3 заметно проще остальных», «варианты 1 и 4 имеют совпадающий ответ», «можно добавить задачу с графиком».

### 4.5 Градация сложности — как считаем

Сложность задания на шкале 1–5 определяется по нескольким параметрам:

| Параметр | Влияние |
|---|---|
| Число шагов решения | +1 уровень за каждые 2 шага сверх минимального |
| Тип когнитивной нагрузки | Воспроизведение = 1, понимание = 2, применение = 3, анализ = 4, оценка/синтез = 5 |
| Абстрактность (наличие переменных, параметров) | +0.5 |
| Объём текста условия | +0.5 при >200 слов |
| Внепредметные связи | +0.5 |

Учитель видит итоговый уровень и может его корректировать вручную в редакторе варианта.

### 4.5 Безопасность, лимиты, конфиденциальность

- **JWT-аутентификация**, refresh tokens
- **Rate limiting через Bucket4j**: 30 запросов к LLM на пользователя в час (бесплатный план)
- **Изоляция данных**: каждое задание привязано к `user_id`, в SQL-запросах всегда фильтр по нему. Row-level security в Postgres.
- **Файлы в MinIO**: каждый бакет с уникальным префиксом `user_{id}/`, доступ только по подписанным URL с TTL 15 минут
- **HTTPS only**, secure cookies
- **GDPR-like удаление**: пользователь может удалить аккаунт → каскадное удаление всех его данных
- **Логирование без PII**: в логах только `user_id`, никакого текста заданий

### 4.6 Форматы вывода

| Формат | Когда используется | Технология |
|---|---|---|
| **PDF** | Печать на принтере | iText 7, шаблоны с полями ФИО/класс/дата |
| **DOCX** | Учитель хочет доработать в Word | docx4j |
| **Персональная ссылка** | Не для этого кейса (для викторин/карточек), но оставим в roadmap | — |
| **Веб-предпросмотр** | До экспорта | React + KaTeX |

Структура PDF-комплекта:
- Титульная страница с метаданными (предмет, класс, тема, дата)
- N страниц вариантов с настраиваемыми колонтитулами и полями для подписи
- Отдельный PDF «Ответы для учителя» (генерируется опционально)

- ✅ Изоляция данных

**Два режима генерации (наша основа):**
- 🎯 **Режим A:** «По эталону» — загрузка готового задания
- 🎯 **Режим B:** «С нуля по критериям» — задание параметров без эталона

**Три способа правки вариантов:**
- 🎯 **Ручная правка** в WYSIWYG-редакторе (Tiptap + KaTeX)
- 🎯 **Промпт-правка одного варианта** — описать на естественном языке, что изменить
- 🎯 **Промпт-правка всего комплекта** — применить изменение ко всем вариантам сразу

**Градация сложности:**
- 🎯 Одинаковая сложность (классический случай)
- 🎯 Возрастающая (базовый → продвинутый → углублённый)
- 🎯 По произвольной шкале (учитель сам задаёт уровни)

**Дополнительные фишки в MVP:**
- 🎯 **Поле дополнительного промпта** на любом этапе («сделай задачи про космос», «избегай дробей»)
- 🎯 **Лента рекомендаций**: «вариант 3 проще остальных», «можно добавить вариант с дробями», «варианты 1 и 4 имеют похожие ответы»
- 🎯 **Оценка времени решения**: каждому варианту и комплекту в целом — прогноз сколько минут уйдёт
- 🎯 **Печатные поля**: настраиваемые поля «ФИО ученика», «класс», «дата», «оценка», «подпись родителя»
- 🎯 **Онбординг-тур**: react-joyride проводит по интерфейсу при первом входе
- 🎯 **Видеогайд**: встроенный плеер с 2-минутным роликом «как сделать первый вариант»
- 🎯 **Большие кнопки + контрастный режим**: специально для возрастных учителей
- 🎯 **Подсказки-тултипы**: на каждой кнопке висит объяснение
- 🎯 **История версий**: откат к предыдущему состоянию комплекта

## 7. Риски и митигация

| Риск | Вероятность | Влияние | Митигация |
|---|---|---|---|
| GigaChat «плывёт» по сложности вариантов | Высокая | Высокое | Двухпроходная генерация: сначала генерация, потом валидация через отдельный промпт. Если валидация не прошла — перегенерируем |
| Rate limit GigaChat в день презентации | Средняя | Критическое | Демо-режим со заранее сгенерированным результатом + платный план Pro на день защиты |
| OCR не справляется с рукописными заданиями | Высокая | Среднее | В MVP заявляем только печатные источники, рукописные — в roadmap |
| Учителя не доверяют ИИ | Высокая | Среднее | Обязательный шаг превью + редактирование, ответы выводим отдельно для проверки |
| Не успеваем все фишки к 22 мая | Средняя | Среднее | Приоритизация: сначала обязательные критерии хакатона, потом фишки. Онбординг и видео — последними |
| Утечка данных учителя | Низкая | Критическое | Row-level security в Postgres, изолированные бакеты в MinIO, аудит-логи всех запросов |
| Парсинг PDF теряет формулы (для физики/математики) | Высокая | Высокое | Используем PDFBox + детектор LaTeX/MathML, в спорных случаях — OCR-проход. Заявляем поддержку как «формулы в виде текста или картинки в задании» |
| Слишком сложный UI для возрастных учителей | Средняя | Высокое | UX-тестирование на 3 учителях 50+ лет до защиты. Большие кнопки, режим «крупный шрифт», обязательный онбординг |
| Защита идёт не по плану / технические сбои | Низкая | Высокое | Запасной скринкаст, локальный билд на ноутбуке у выступающего |
